03 · Schemas

    
Deterministic contracts

    
Every output lands in this exact JSON shape. No free-text parsing, no "interpret the model's intent."


    

      

        
        wf-01-triage/schema.json
        
      


// Deterministic contract for triage output
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "title": "TriageDecision",
  "type": "object",
  "required": ["ticket_id", "severity", "category", "routing", "confidence"],
  "properties": {
    "ticket_id":    { "type": "string", "pattern": "^[A-Z]{3}-[0-9]{4,6}$" },
    "severity":    { "type": "string", "enum": ["P1","P2","P3","P4"] },
    "category":    { "type": "string", "enum": ["billing","bug","how-to","security","other"] },
    "routing":     { "type": "string", "enum": ["team-billing","team-eng","team-cs","team-sec"] },
    "confidence":  { "type": "number", "minimum": 0, "maximum": 1 },
    "needs_human": { "type": "boolean"}
  },
  "additionalProperties": false
}

    


 
All5 workflows ship a matching JSON schema. Enforced via Zod-equivalent runtime check in the included Lambda handler.
